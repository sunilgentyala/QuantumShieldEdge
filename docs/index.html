QuantumShield-Edge
QKD-keyed hierarchical federated learning

Leaf devices train, edge aggregation nodes defend against Byzantine updates, and the edge-to-cloud link is sealed with a real one-time pad paid for from a QKD key pool. Every number on this page is generated by the code in the repository.

Scope, stated plainly. The QKD layer is emulated: key bytes come from a seeded generator standing in for QKD output, so the simulator exercises the code paths and key arithmetic but is not itself a cryptographic result. Leaf-to-edge links are assumed post-quantum protected and are not simulated. No claim of quantum advantage is made.
What is executed

Nothing on this page is hand-written

Each component below runs in the simulator and is covered by tests. Results are regenerated from per-run JSON files by the scripts in experiments/.

Transport

Sealed messages

One-time pad with a Wegman-Carter polynomial-hash tag over GF(261-1), sparse fp16 wire format, exact key accounting. The cloud aggregates only what it decrypted and verified.

QKD

Link and key-pool model

Asymptotic and finite-key secret fraction, key pools with atomic withdrawal, and a protocol-level BB84 Monte Carlo including eavesdropper abort.

Policy

Shortage policies

adapt, wait, defer and pq, with pq explicitly counted as not information-theoretically protected.

Threats

Attacks and aggregators

Omniscient min-max and ALIE alongside simple attacks, against FedAvg, Krum, median, trimmed mean and detector-weighted aggregation.

Detection

Quantum vs classical

A 4-qubit, 24-parameter variational circuit (exact 16x16 unitary) compared with a size-matched MLP, a linear model and trigonometric-encoding controls on identical inputs.

Data

Heterogeneous clients

CIFAR-10 split by Dirichlet label skew across 50 leaves in 4 edge clusters, trained with a 24,458-parameter CNN.

Architecture

Three tiers, one sealed link

Leaf devices send updates to an edge aggregation node. The node runs the defence, then sends a sparsified, sealed update to the cloud over a QKD-keyed link. The cloud returns a sealed model delta.

Detector weighting helps

Under sign flip and min-max, both detectors recover several accuracy points over FedAvg and the robust statistics, and match FedAvg when there is no attack.

No in-distribution quantum advantage

The 24-parameter circuit and a 25-parameter MLP perform alike on attacks seen in training. We report this plainly.

Label flipping is not detected

Detection sits at chance for every model. The fingerprint features capture update geometry, not label semantics.

Leave-one-attack-out: balanced accuracy over 8 seeds

The detector is trained without one attack and tested on it. The circuit leads, but classical models with a trigonometric input encoding close part of the gap, so the encoding explains some of the effect and the circuit still ranks first.

Key budget

Quantum keys are a budget, and the policy decides who pays

A one-time pad consumes exactly as many key bits as the message has bits. At 5% sparsity each link needs 76,096 key bits per round, a figure the code computes exactly. When supply falls short, the shortage policy picks the loss. Results below are at key supply 0.14x of demand.

adapt

92% still pad-protected

Sparsifies harder to fit the key budget. Accuracy drops to 24.8%.

wait

100% pad-protected

Holds the update until keys arrive. Security and accuracy stay intact; the cost is about 382 seconds of delay per round.

defer

Accuracy collapses

Skips rounds without keys. Only 13% of messages are protected and accuracy falls to chance (10.0%).

pq

Accuracy kept, protection lost

Falls back to post-quantum-only. Accuracy holds at 30.3% but 87% of traffic loses information-theoretic protection.

Code

Reproduce everything

Runs are resumable, one JSON per run. All tables and figures are generated from those files. Throughput on a laptop CPU is about one FL round per second in aggregate.

# install and test
pip install -r requirements.txt
python -m pytest tests -q            # 22 tests

# train detectors, run the main matrix, build tables and figures
python experiments/pretrain_detectors.py
python experiments/run_experiments.py main 4
python experiments/run_experiments.py keyrate 4
python experiments/key_analysis.py
python experiments/loo_seeds.py 8
python experiments/analyze.py

Limitations

  • Small model and short training, about 35% accuracy on the ideal channel.
  • Few seeds for end-to-end runs, so several differences are within noise.
  • Emulated QKD without decoy-state estimation or device imperfections; the finite-key bound follows the structure of the tight bound and is not a device security proof.
  • Omniscient but detector-unaware attackers, and reliable ordered delivery assumed between edge and cloud.
